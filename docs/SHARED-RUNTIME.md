# 共享核心、总插件库与独立运行目录

开发团队：流光工作室 · 作者：流光-Pigeon-X

## 目录与所有权

```text
UTSl-Manager.exe
Core/Engines/UnifierTSL-<名称>-r0001/ 已收录的 UTSL 核心与代码依赖
Plugins/                            每个插件仅一个当前版本 DLL
Plugins/Archive/                    历史版本集中归档，可读取和回退
Data/Library/Plugins/                插件版本与 SHA256 清单
Data/Library/plugin-library.json     主库当前版本索引
Server/0.<名称>/                     此服持久配置、账号数据及原包内容
Server/1.<名称>/                     另一服的持久数据
Server/World/                        显式迁移后的集中地图目录
Core/Runtime/0.<名称>/                与 Server 目录同名的当前运行沙箱
Core/Runtime/.manager-slots/<服ID>/previous/  至多一个上一版回退沙箱
Data/runtime-slots/                  命名沙箱归属与切换记录
Data/runtime-failures/               已核验的失败准备诊断归档
Data/runtime-selections/             每服核心与插件精确版本选择
Data/runtime-runs/                   实际启动的进程身份与沙箱路径
```

管理器后台负责准备工作目录和创建 UTSL 进程；Avalonia 界面通过本机用户专用管道控制后台。UTSL 不在 UI 线程运行，地图生成器仍嵌入管理器。三个世界属于同一 UTSL 进程，按已有的顺序启动规则加载；多个 UTSL 进程仍按名册编号顺序启动。

运行功能全部在 C# 内完成：Host 通过 Win32 创建服务端进程，硬链接和持久目录 junction 直接调用 Windows API；不调用 `cmd /c mklink`，也不生成或执行 BAT、CMD、PowerShell 启停脚本。地图工坊直接运行 C# 生成器和 worker。开发构建及测试脚本不属于交付程序的运行依赖。

总库负责维护二进制版本，不保存各服的配置、玩家数据库或世界。两个服务器可以选择相同 DLL，也可以选择同名 DLL 的不同 SHA256。版本选择必须明确，不能把目录里出现的所有插件自动视为已启用。

## 使用步骤

1. 停止待配置的目标服，打开总插件库，选择目标服务器。
2. 可先从此服收录原有插件和核心，保留原包作为迁移与回退依据。收录不会自动启用沙箱或切换核心。
3. 选择核心版本、需要的插件及精确版本，启用独立运行沙箱并保存。
4. 可先准备运行目录；准备操作只校验与落盘，不创建服务端进程。
5. 从管理器启动。后台再次核验选择与输入 SHA256，准备新的运行代次，再创建进程；全部世界就绪后才启动队列中的下一服。

插件 DLL 在同卷支持的情况下使用硬链接，避免为每服再保存一套相同插件字节；无法建立硬链接时使用 SHA256 校验后的复制，并在运行清单记录方式。配置与玩家数据映射回各自服务器的持久目录；显式迁移后，世界统一映射到 Server/World，各服地图必须使用不同文件名。

停止目标服后，可在总插件库选择“整理为命名沙箱 · 保留一个上一版”。后台先验证旧运行目录的完整文件清单、SHA256、归属及持久映射，再保留最近一版并清理已核验的旧代次。未知内容或链接异常会阻断迁移并保留原件。未明确迁移的旧工作区继续使用 run-0001 等目录，不在启动时偷偷清理。

启用后，当前沙箱直接采用 Server 内的目录名；准备在固定 pending 槽完成，成功后才替换当前目录，上一版仅保留一份。准备失败保持当前目录，诊断使用同一个固定槽，不无限新增目录。事务中断时保留记录并阻断自动重试，需要核查后恢复。目录数量减少主要节约磁盘空间；停止的目录本身不占进程内存。清单仍保留唯一代次 ID，实际进程身份包含 PID、创建时间和沙箱内的完整 EXE 路径。后台重启后仍识别已存在的沙箱进程为外部运行，拒绝重复启动或接管停止。实际目录和清单由 `ServerState.RuntimeDirectory` / `RuntimeManifest` 返回。

## 更新与回退

导入新插件会添加一个不可覆盖的内容寻址版本，主目录每个程序集只显示一个规范 DLL；旧版本自动归入 Plugins/Archive，不再生成 -variant-01 文件。不同 AssemblyVersion 按数值比较，较旧版本的导入不会自动降级；相同 AssemblyVersion 的新 SHA256 按新修订处理，重复导入旧 SHA 不反向切换。

首次整理优先采用各服一致选中的精确 SHA256，避免同版本旧件覆盖已部署修复。主库页默认只显示当前版本；勾选“查看历史”可读取归档，高亮历史版本后点击“设为当前版本”恢复主库。回退不会自动改动各服选择：目标服停止后，在列表勾选所需精确版本并保存，下一次启动生效。各服选插件的范围独立，专属插件不会被强行启用到所有服务器。

归档保留原始 DLL 大小与 SHA256；内容库对象缺失时可从归档核验恢复。首次通过“整理归档”明确启用托管库；未启用的旧工作区保持原导入行为，不自动迁移。启用后后台启动、收录和再次整理都走同一 C# 实现，以跨Session进程间文件锁串行更新。先校验归档，再写可恢复的待处理计划，然后原子替换目录项，不原地修改硬链接字节。中途失败留下计划，下一次整理继续；出现未知内容、篡改或路径异常时拒绝。原始版本、旧选择、已运行代次与旧核心不被隐式删除。

各服仍使用保存时锁定的 SHA256；导入库不修改运行中的插件，不执行热载。核心版本通过整套代码文件清单锁定，Game 与 Live 的不同核心不会自动合并。

导入依赖校验失败会保留导入计划。若尚未提交主目录，可用“取消失败导入”保存拒绝记录、隔离未完成版本，再修正依赖后重新收录；已经提交的导入必须先恢复事务，不能用取消跳过校验。

禁用独立沙箱后沿用原包启动方式。旧的“备份并复制插件”功能保留为兼容操作，其目的地是原服目录，与按服沙箱选择不同。正在运行、外部运行或停止失败的目标服不能修改运行选择。

## 校验和限制

原包与代码输入不允许越界或任意重解析点。运行目录中的受控持久映射单独创建和校验。损坏的库文件、清单与实际字节不一致、重复程序集选择，均应在创建进程前拒绝。启动准备失败保留诊断材料，不递归删除持久映射目标。

这是进程与数据目录隔离，不是 Windows 权限安全沙箱。插件仍以同一 Windows 用户权限运行；不能借此隔离恶意插件。硬链接共享的是磁盘文件内容，各 UTSL 仍在各自进程中加载程序集与静态状态。管理员直接改写硬链接文件会影响共享字节，必须通过管理器追加新版本；后续准备会核验库 SHA。

本地夹具的 DLL 加载、版本选择、文件身份、持久数据与进程生命周期结果属于组件验收。真实 UTSL 插件的完整依赖派发、玩家登录、跨世界传送和渲染，需要对应的游戏验证，不能由目录准备或健康接口代替。
