# 配套核心接口

`core-world-startup-and-console.patch` 是维护中的 UTSL 核心窄补丁，不包含游戏引擎、配置、插件或编译产物。本管理器本身的源码可独立构建。

补丁适用于已经拥有 `Surface/Hosting/Unified/UnifiedConsoleHub.cs` 的维护分支，不能无检查覆盖上游或不同分服源码。两服应从各自已验证的源码状态分别应用、构建，保留既有分服差异。

改动范围：

- 自动启动器依次创建世界，等待 `IsRunning`（volatile backing field）后才启动下个世界；原生线程提前退出或超时即暂停。
- 管理器通过每次进程启动新建的 `UTSL_MANAGER_PIPE` 开启本地当前用户命名管道，仅提供精确世界名的读取/输入；每世界回放上限约一百万字符，输入队列上限64条。
- 世界输入拒绝空值、多行、空字符和未知或停止的世界；不把未知世界命令改发宿主。
- 托管模式的宿主输入保留协调器语义，`/off` 不会落到当前某一个世界；没有该环境变量时沿用原控制台行为。

管理器在启动下一台 UTSL 前还会通过本机 REST 复核所有配置世界：`/world/list` 的精确名称、running、有效尺寸，以及各世界 `/v2/server/status` 的实际成功状态。HTTP200本身不足以证明世界已运行。

`src/CoreTests` 对指定实际核心 DLL 的内部接口进行组件验证；`src/StartupTests` 使用本地 ConPTY/REST 夹具验证队列和停止所有权。它们不能替代真实原生世界加载和玩家游戏验收。
